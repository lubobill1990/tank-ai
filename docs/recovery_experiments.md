# 有限预算恢复实验

此前约 1046 万步训练的长期评测没有稳定通关，模型与录像保留，
但该运行不再自动续训。此工具用于找到“值得继续投入的证据”，不是自动搜索胜利模型。

## 状态修正与技能评测

当前环境版本为 `grid26-events-v7-clean-terrain`。它修正 RAM 地图中
bit7 临时占位信息被误识别成静态墙的问题，47 通道的布局不变。

`skills.py` 提供六种真实 NES 场景：
`shoot`、`dodge`、`counter`、`demolish`、`pickup`、`defend`。
每种有两个几何变体。只有这个明确命名的测试环境在 reset 初始化 RAM；
后续移动、命中、道具、损命均由原版模拟器执行。它不替换普通游戏环境。

技能报告的 `objective` 表示场景目标成功，**绝不计入完整关卡胜率**。
反例控制必须排除站着不动、让子弹撞墙/出界等伪成功。场景可解也不意味着
当前启发式能解；基线失败照实保留，不通过放宽定义来让某个策略好看。

## 四组单变量对照

| 组 | 权重起点 | gamma | 训练奖励 |
| --- | --- | --- | --- |
| baseline | 随机初始化 | 0.99 | shaped |
| warm | 已审核的 v6 模型权重 | 0.99 | shaped |
| horizon | 随机初始化 | 0.997 | shaped |
| sparse | 随机初始化 | 0.99 | sparse |

`sparse` 只保留时间、真实击杀、死亡、通关和基地失败项。训练动作、物理规则、
观测和终点不变。评测所有组都使用统一的 shaped 环境；不以不同训练奖励的数值选胜者。
warm 只复制权重，不复制旧优化器或步数，并记录原 checkpoint 哈希和迁移来源。

训练只使用第 1 关完整回合，两个种子 0/1。模型选择使用 101/202，
最后独立确认使用 1001/2002，不参与选择。NES 全局随机性只有有限的初始等待变化，
所以这些种子不是大量独立地图；还不能据此声称能泛化到别的关卡。

## 执行

```powershell
uv run --no-sync python ablation.py `
  --output-dir runs\recovery-comparison `
  --warm-source runs\20260928-boundary-continue347136-g099\checkpoints\step-000010458624.zip `
  --steps-per-trial 50000 --eval-every 25000 `
  --seeds 0,1 --parallel 2 --device cuda `
  --max-wall-seconds 2700 --patience 3
```

输出目录必须不存在。最多同时两个训练子进程，每个有两个 NES 环境；
每个线程数受限，所有子进程有独立日志和状态。

- 请求预算 8×50,000=400,000 步；完整 rollout 向上取整后最多 **401,408 步**。
- 默认每个 trial 在 0、25,088、50,176 步评测，不在优化前保存“已训练”进度。
- 每个 trial 墙钟预算包含初始化与评测；超时停止，外层 watchdog 最多再等 60 秒清理。
- 非有限数值判失败；连续三次评测无改善、到步数上限或墙钟上限会停止。
  默认只有两次训练后评测，通常先碰到步数上限；调短评测间隔可更早触发耐心门槛。
- 不自动重试失败 trial，不自动增加预算，也不自动恢复旧长训练。

改任何受签名覆盖的运行代码后，正在运行的 batch 会明确拒绝继续。
不要边改评测定义边训练。配置、奖励 profile、源文件、ROM 和技能协议都进入签名。

## 结果文件

- `batch.json`：任务排队/运行/结束状态、PID、命令和日志位置。
- `configs/`：每组不可变配置。
- `logs/`：各 trial 输出和明确失败原因。
- `trials/<arm>-seed-<seed>/checks/`：每次完整关卡与技能原始评测。
- 每个 trial 的 `best.zip`、`final.zip`、manifest、`result.json`。
- `confirmation.json`：只用于最后确认，不能反过来选模型。
- `report.json`：所有 trial 的前后指标、实际预算、停训原因和局限。

实验 checkpoint 使用 **lab manifest**，与正常长训练 manifest 明确区分。
通过 `ablation.load_lab_checkpoint` 显式读取，不可直接传给普通 `train.py --resume`
或 `watch.py` 冒充相同实验。若要推广某组配置，先评审数据，再建立正式新实验。

## 如何解释

选择顺序是“确定性完整关卡获胜数，再看平均技能成功率”，而不是混合奖励。
始终同时查看两个训练种子、采样模式、六项技能和未参与选择的确认结果。
技能提升但仍零通关，只能称为基础能力进展；一次两局中的胜利不足以说明稳定。
短预算全零不能证明算法永远学不会，但足以阻止自动投入另一轮千万步。
