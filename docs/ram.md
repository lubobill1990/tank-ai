# 本地 ROM 的 RAM 校准记录

2026-09-27：通过本地 6502 指令流检查和真实模拟器的逐帧受控实验校准。
结论只适用于当前 `battle_city.nes`；每次实验保存 ROM SHA256，换 ROM 不自动兼容。
回归见 `test_game_state.py`、`test_environment.py`，无需安装逆向工具即可运行。

## 活动对象与坐标

| 数据 | 地址与规则 |
| --- | --- |
| 坦克 X/Y | `0x90+i` / `0x98+i`，**中心坐标**，16px 包围盒 |
| 坦克状态/朝向 | `0xA0+i`，`0x80 ≤ 值 < 0xE0` 才活动；低两位为 ROM 的上/左/下/右 |
| 坦克槽 | 0=P1，1=P2，2–7=敌人；本项目为单人游戏 |
| 生成/爆炸 | `0xE0` 以上为生成动画；受击后进入 `0x73` 并递减，不能当成活坦克 |
| 玩家永久火力 | `0x101`，`0x00/0x20/0x40/0x60` 对应 0–3 星；当前属性同步在 `0xA8` |
| 敌人剩余装甲 | `0xA8+i` 低两位＋1；闪烁重坦 `0xE4` 是特殊编码，仍为 4 发 |
| 敌人携带道具 | `0xA8+i & 0x04`；仅用于敌人，记录为 `Tank.drops_item` |
| 护盾 / 冻结 | `0x89` / `0x100` 非零 |

公共 Python 朝向为上=0、下=1、左=2、右=3，解码时转换 ROM 顺序。
重坦受损分支在掉落道具后将 `0xE4` 转为 `0xE3` 再减至 `0xE2`，
所以首发后仍需三发；不能把闪烁重坦的低两位 0 解释为只有一层装甲。
实测该首发产生场上道具，击杀数仍为 0；所以掉落事件与死亡事件分别统计。
普通敌人和红坦仅在携带标志上不同时，必须在观测中可区分。
ROM 的定位/碰撞代码明确先从坦克坐标减 8（例如 `$E18F` 附近）；
出生点 `(88,216)` 实际占据行 24–25、列 8–9。
输入、RAM 更新和渲染存在流水延迟，像素对齐实验需停止移动后等待两帧。

## 子弹与发射

| 数据 | 地址与规则 |
| --- | --- |
| X/Y | `0xB8+i` / `0xC2+i`，**共 10 槽**，不能只读 6 槽 |
| 状态/朝向 | `0xCC+i`，高半字节 `0x40` 才是飞行子弹，低两位是方向 |
| 速度属性 | `0xD6+i`，bit0=0 为 2px/帧，bit0=1 为 4px/帧 |
| 归属 | 槽 `i & 7`；P1 的两发分别在 0、8，P2 在 1、9 |
| 可再次发射 | 主槽状态为 0；或 ≥2 星且备用槽状态为 0 |
| 实际发射脉冲 | `0x030F` 进入 1；单人模式下由真实发射例程触发 |

重要：**失效子弹的坐标不会自动归零**。爆炸状态 `0x33` 也不是飞行子弹，
但会占用槽直到状态归零，不能仅按屏幕内子弹数量判断能否开火。

ROM `$E08C` 例程只有在槽可用时创建子弹并发出声音事件；逐帧实测声音请求值
从 0/2 进入 1 时对应一次发射。即使子弹在该帧立即相消，这个事件仍能记录实际开炮。
不使用“按下 A”的次数代替发射次数。

ROM `$E122` 附近的双发逻辑会把原主槽子弹搬到备用槽再创建新主槽子弹。
`StateTracker` 保留被搬运子弹的 generation，重新使用空槽时分配新身份。
速度直接由 ROM 方向/速度属性得到，不靠最近邻配对，也不受动作掩码调用次数影响。

## 击杀、掉命、基地与清关

- 真死亡：活动坦克进入爆炸状态。对每个 NES 帧检查，命中装甲不误计，
  炸弹造成的敌人死亡也计入。
- `0x73..0x76` 是 P1 分敌人类型的**炮击击杀计数**，可辅助验证，但炸弹清敌不增加它。
  有状态的 tracker 统计真实死亡事件，不能只依赖这四个计数。
- `0x51` 是剩余生命。真实死亡发生后，爆炸动画结束才扣命；不能用扣命延迟来判定是否躲弹成功。
- `0x68 == 0x80` 表示基地完好；不同值表示基地已毁。不要使用旧的 `0x2C/0x34` 猜测。
- `0x7F` 是待生成敌人数；`0x80` 是包括在场/待生成在内的剩余敌人数，
  会在敌人死亡动画结束后递减。`0x80 == 0` 对应本关清除。
- `0x85` 是关卡号。环境在关卡清除时结束，不必操作结算页面等待关卡数字递增。

## 道具与分数

- 道具位置：`0x86` / `0x87`；类型：`0x88`。
- 可领取条件：X 非零、`0x62 == 0`、类型在 0–5。
- 类型：0 护盾、1 冻结、2 铲子、3 星、4 炸弹、5 加命。
- 领取时 `0x62` 被设为 50（随后逐帧递减），坐标暂时保留用于积分显示；
  `0x49` 是领取检查中的玩家循环索引，**不是“场上存在道具”的标志**。
- 领取事件需从可领取状态进入领取倒计时，且领取者索引为 P1。
- `0x15..0x1B` 是十进制分数位，`0x19` 是其中的百位，**不是击杀计数**。
  不同坦克分数不同，拾取道具加 500，分数进位也会使该字节减少。

实测六种拾取均令分数增加 500；星使 `0x101/0xA8` 增加 `0x20`，
护盾/冻结计数设为 10，加命令 `0x51` 增加 1。
这些受控 RAM 设置只用于回归测试，训练课程不靠它们伪造局面。

## 地形

原生窗口是 `[16,224)²`，8px 格，RAM 行步长 32、起始 `0x400`，
读取内存行列 2–27，不做 2×2 汇聚。

| 原始值 | 类型 |
| --- | --- |
| 0、32、34 | 空地 / 环境 / 森林，坦克和子弹可通过 |
| 1–15 | 残砖四位掩码：1 左上、2 右上、4 左下、8 右下，每块 4×4px |
| 16 | 钢，基础火力不可破坏 |
| 18 | 水，只阻挡坦克 |
| 33 | 冰，可通过 |
| 200–203 | 完好基地 |
| 204–207 | 被毁基地图块，终止状态下出现 |

未知值明确告警并按不可拆墙处理，不静默猜成砖。模型和启发式使用同一解码。

### 临时占位位（v7 修正）

ROM 在坦克占据的地图单元上临时置 bit7（`$E1F3` 的 ORA `0x80`），随后在
`$E234` 清除此位。一次 NES 帧边界不保证刚好位于清理完成之后，因此读取快照时
可能看到 `0x80`（占用空地）、`0xA0`（占用环境格）、`0xA2`（占用森林）等。

`terrain_value` 仅对低 7 位属于已验证材料集合的值移除占位位；材料与残砖位都使用
同一规范化值。200–207 的基地图块不能盲目 `&0x7F`，未知字节仍须告警。
动态坦克继续由对象槽表表示，不伪装成静态墙。

真实旧模型回放已复现含占位位的策略观测；修正后逐格验证这些单元恢复底层材料，
不是通过隐藏 warning 消除问题。该修复不承诺旧策略自动变强，需重新对照评测。

### 残砖的两种碰撞精度

`GameState.terrain` 保留 26×26 的材料类别，`brick_masks` 同尺寸保留原始四位掩码，
两个数组不可写且随 RAM 一起更新。即使材料仍然是砖，`15→1` 也必须更新残砖状态。
这不是两套世界模型，而是同一状态的材料与剩余形状。

- **坦克**：ROM `$DCD5/$DCFA` 读取整个 8px 单元，非零且小于 `0x20` 就阻挡；
  并不根据残砖小块为空就允许坦克通过。
- **子弹**：ROM `$D725` 根据 `x & 4`、`y & 4` 选择低四位中的一个；
  `$D73C/$D743` 检查/清除该位。射击细节相当于 52×52 的 4px 格。
- 子弹检查垂直方向的 `x` 和 `x−1` 两条采样线，水平方向的 `y` 和 `y−1`；
  不能用对称的 ±2px 子弹宽度替代残砖命中判断。

实测出生点右侧前方设置残砖 `1` 时，坦克被整个单元挡住，持续向右开火仍打不到
左上残块；改为 `8` 或 `15` 则能清掉。这说明仅扩大网络分辨率不够，
拆砖控制必须区分“阻挡行走”和“当前炮口能否命中剩余部分”，并调整射击位置或绕路。
