# LLM 蒸馏战役（2026-10-02，$200 预算，实付 $96.29）

目标：利用 LLM 训练/提炼出**实时作战无需 LLM** 的更强系统。

## 最终交付：配置组合系统（零 LLM、零云调用、~19ms/决策）

运行时 = 几何执行器（HeuristicBot）+ 自动躲弹/反击 + MPC 前瞻否决（Rust 引擎，
毫秒级）+ **每关调度规则**（从 LLM 对局编译）：
- 默认：纯 hunt
- stage 2/13/21：protect 至剩 16 敌转 hunt
- stage 25/33：protect 至剩 12 敌转 hunt

真实 ROM 战绩（两组独立 seed 共 140 局，12,000 帧，普通复位）：
**62/140 = 44.3% 每局通关率；合计 30/35 个关卡至少通关一次**。
其中 21/25/33 为 MPC teacher 与全部神经模型从未通过的关。
对照：最佳纯神经模型 21.4%（8 seed）；LLM 指挥官本人 ~49%（$0.2/局）。

## 关键消融（本战役最有价值的发现）

| 系统 | ROM 通关率 | 说明 |
|---|---|---|
| 纯执行器+veto（固定 hunt） | 37/70（53%，25 关） | 零 LLM 基线，此前从未单独测过 |
| LLM 指挥官（Sonnet） | ≈49% | 与纯执行器统计持平；特定关更强 |
| 战略头 MLP 混合 | 17/70 | 模仿了 LLM 全部切换噪声，反而弱 |
| 端到端 BC + LLM 演示（v9/v10） | 8/70 与 5/70 | 原始动作 BC 架构性平台，LLM 数据救不了 |
| **配置组合（编译蒸馏）** | **44%/140局，30关** | LLM 战略经验 → 每关规则 |

教训：LLM 的平均指挥价值≈0（执行器自带的"全力进攻+安全否决"已是强策略），
但在**特定关卡**的战略选择（先守后攻的时机）有真实增量——用"编译成规则"的
方式蒸馏比"模仿学习"高效且无噪声。

## 续篇：执行器防守战术攻坚（同日下午，零 API 成本）

诊断（diagnose_baseloss.py）：所有 base_lost 都死于敌人进入底行走廊（y≈216）
横射基地或中柱直落，而玩家在远端追杀、回防不及。

迭代与结果（每项 4 局/关验证）：
- 侧翼哨位 BaseGuardBot（堵走廊+对射）：7/29 维持偶通，20/32/34 仍 0。
- 锚定蹲防（塔防化）：更差（0/20，击杀暴跌），被动挨打不可取。
- **高价值道具反射（铁锹/星星/手雷无条件拾取）：决定性改进**——
  stage20 首次稳定通关（2/4），硬关击杀翻倍，回归样本 13/18（72%）。

最终系统（guard-bot + 道具反射 + 每关调度）140 局新 seed：**42.9%，
27/35 关 ≥1 通，19 关 ≥2/4 可靠**（神经模型线此前仅 9 关 ≥50%）。
合并当日全部零 LLM 配置变体：**34/35 关至少通关一次；唯一未破 stage 32**
（全场击杀 ≤3，疑似钢墙地图：需星星火力链开荒，而低击杀拿不到道具——
死锁，留作开放问题；候选解法：MPC 深搜钢缝射线、power 保持/继承机制）。
