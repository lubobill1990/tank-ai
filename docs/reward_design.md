# 奖励、终点和观测

实现入口：`battle_city_env.py`。状态与事件来自 `game_state.StateTracker`；
每个手柄决策默认执行 4 个 NES 帧，**每帧都采集事件**，观测仅在决策边界生成。

## 奖励分项

`info["reward_components"]` 是本次 step 的增量，所有分项之和严格等于返回 reward。

| 分项 | 数值与条件 |
| --- | --- |
| `time` | 每实际执行的 NES 帧 −0.0005，四帧为 −0.002 |
| `kill` | 每个真实敌人死亡 +1；装甲受损不算死亡，炸弹击杀也计入 |
| `death` | 玩家从活动状态进入爆炸状态立即 −3，不等延迟扣命，也不重复扣 |
| `clear` | 完整关卡胜利 +5；课程成功 +1，但 outcome 必须为 `objective` |
| `base_loss` | 基地被毁 −20 |
| `danger` | 每次决策 −0.05×危险度，危险度为最近敌人到基地中心曼哈顿距离在 96px 内的线性值 |
| `guard` | 每个击杀额外 +击杀前危险度 |
| `evasion` | +0.05：原威胁子弹身份不再构成威胁、玩家仍活动，且本 step 没有死亡 |
| `pickup` | 加命 +2；升星 +1（满级 +0.5）；护盾 +0.7；其余 +0.5 |
| `base_fire` | 每次**实际发射**的首个碰撞对象为基地 −0.5；隔着砖/敌人不算直击基地 |
| `steel_fire` | 每次实际发射的首个碰撞对象为钢 −0.05；3 星豁免 |
| `boundary_fire` | 贴住场地外边界并朝外实际发射 −0.05；不处罚场内空射线或朝场内射击 |

不再有“按键反向就处罚”的横跳项。请求开火但子弹槽未空，不视为一次发射。
这组数值不是最优超参结论；调整时必须使用固定通关评测，并检查各分项量级。

v7 恢复实验增加 `reward_profile`，不改变 ROM 动作、观测或终点：
`shaped` 保留上述所有分项；`sparse` 只保留 `time/kill/death/clear/base_loss`，
其余分项仍在返回字典中但置零。掉落/拾取/发射等计数继续正常统计。
profile 进入运行签名，不能把不同奖励实验当作同一配置无提示续训。

`danger` 是非势能塑形，仍可能偏置策略；最近敌人距离也不等价于真实基地危险。
目前保留明确分项以支持后续消融，而不是声称奖励设计已经解决所有策略问题。

## 终点

判定优先级：基地被毁 → 命耗尽 → 完整清关 → 课程目标 → 超时。
最后一条命的真实死亡即可判负，不必等爆炸动画后生命计数归零。
有剩余生命的死亡继续回合，保留原版复活过程。

- `clear`：仅完整关卡胜利。
- `base_lost`、`lives_exhausted`：失败。
- `objective`：击杀/防守课程目标完成，不算通关。
- `timeout`：截断，非真正游戏结束。

课程 `combat` 要求至少一个击杀；首次达标时若有道具在场，不立即结束，
而是等到拾取、道具离场，或最多 600 NES 帧（10 秒）的窗口结束。
窗口不会因后续掉落而刷新。没有道具时保持原来的即时目标完成。
`defense` 要求至少 900 帧且至少两个击杀。
它们使用真实关卡，不是假设只有一个敌人的人工游戏，也不是通过升星/删敌修改的训练局面。

## 观测（47×26×26）

确切顺序由 `CHANNEL_NAMES` 定义：

- 砖、钢/未知、水、冰、基地；
- 玩家位置和真实朝向；
- 敌人位置、真实朝向、剩余装甲；
- 敌我子弹位置、按像素/帧编码的速度；
- 剩余敌人、待生成敌人、命数、星级、护盾、冻结、可否再次发射；
- 六种道具的空间通道；
- 上一个宏动作、剩余时间、两个课程任务标记；
- 追加四个残砖位平面（左上、右上、左下、右下）；
- 追加玩家格内 X/Y 偏移，值为 `((坐标−16)%8)/7`，只填在玩家占用格。
- 追加 `bullet_danger`：考虑坦克命中范围和地形遮挡的短期危险强度。
- 追加 `enemy_drops_item`：在仍携带道具的敌人占用格填 1。

坦克以 RAM 中心 `(x,y)` 的 `[x−8,x+8)×[y−8,y+8)` 投影，占 2×2 至 3×3 个格。
旧 45 个通道顺序不变，危险图和携带道具标记追加在末尾；
47 通道堆叠两帧后为 94×26×26。
没有 13×13 汇聚地图，也不需要把所有观测平面扩成 52×52。
道具只在真正可领取时出现，死亡/生成动画和失效子弹的残留坐标不进入活动对象通道。

动作掩码查询只读当前快照，不更新速度或身份；允许的 15 个动作保留原始动作细控能力。
坦克通行遵循原版整 8px 格阻挡；射击和拆砖检查保留四个 4px 残块，
避免炮口穿过缺口却把它误判为可清除的路障。

## 对轰与朝基地方向开火

- 偏离坦克中心线的子弹仍可能擦到履带。启发式按完整坦克命中范围预测威胁，
  不是只检查同行 / 同列；实测横向偏移 5、8、9px 的竖直来弹都能击毁玩家。
- **能命中坦克不等于能与我方子弹相撞**。COUNTER 的掩码和启发式共享同一判断：
  必须有可用发射槽、满足弹与弹对齐、且射线路径可用。侧面来弹可以启用 DODGE，
  但不因“存在威胁”就启用 COUNTER。
- 无法发射时启发式优先尝试躲避，不再回退到攻击 / 无效对轰。若没有可用躲避动作，
  返回 NOOP，不声称能保证避开；原始移动动作仍保留给学习策略。
- 朝基地的方向**不是禁射条件**。首个实际碰撞物是砖或敌人时允许射击，
  包括基地外围砖墙；若残砖缺口让射线直接命中基地，启发式拒绝该射击。
  原始动作仍保持软惩罚规则：真正发射且首碰基地时扣 `base_fire`。
- 每次决策重新检查当前残砖。前一发有砖挡住，不代表拆掉后下一发仍允许朝基地打。

### 子弹危险区域

`bullet_danger` 是第 46 个通道，形状 26×26。格 `(r,c)` 代表坦克中心位于
`(16+8c,16+8r)` 的锚点，与现有中心点编码一致；玩家偏移通道保留格内精确位置。

- 对每颗当前敌弹计算静止坦克的最早可能命中时间，未来范围 **24 NES 帧（0.4 秒）**。
- ROM 的命中条件为两个轴的距离都小于 10px，所以采用 ±9px 范围，
  不是单像素子弹中心线。模型能直接看到擦履带也危险的带状区域。
- 使用与启发式同一套残砖射线判断；子弹在当前地形的第一碰撞处截断，
  水 / 冰 / 森林不截断。残砖缺口按 4px 掩码处理。
- 无预计命中为 0；命中时间 `t` 对应 `(25−t)/25`，越近越大；多颗敌弹取最大值。
  P1/P2 友方子弹不产生危险。不能容纳完整坦克的场地外缘锚点为 0。
- 这是**无护盾的静止坦克、当前子弹与当前地形**的短期几何提示，不是死亡概率，
  也不是可通行图。不预测未来新发射、主动躲避、对轰或连发拆墙后的变化，每次决策重算。
  护盾、位置、速度等原始通道仍保留给模型综合判断。

此通道只补充表征，不新增奖励项或替模型强制选择动作。

### 外边界无效动作

坦克中心的合法边界为 24–216px。已经朝向对应外侧、又贴住该边界时，
重复同方向移动、同方向移动＋开火、纯开火被动作掩码关闭。
NOOP、朝场内或沿边界移动仍合法。若当前朝向不同，转向动作仍保留：
真实 ROM 中转向可能把格内偏移吸附到有效位置，不能一刀切禁掉所有向外按键。

`shot_obstacle` 仅把炮口立即出界的射击分类为 `boundary`；
场内没有目标的普通射线仍是 `none`，避免把预射或正常掩护火力都算成浪费。

诊断指标与奖励分开：

- `stagnation_frames`：玩家位置、击杀、拾取均无进展的时长。敌人拆墙或临时占位位变化
  不再将它清零；它也可能包含合法原地瞄准，不据此直接扣分。
- `boundary_waste_frames`：累计执行无效贴边向外动作的帧数。
- `boundary_waste_streak_frames` / `max_boundary_waste_frames`：当前 / 最长连续无效边界动作。
  有实际位移或转向则不计为无效边界动作，普通守点 NOOP 也不计入。
- 评测 `boundary_waste_rate` 为累计无效边界动作帧数 / 总帧数。

### 红坦与道具机会

“红坦”按 RAM 中的携带道具标志识别，而非额外读取画面。
红色重坦第一次命中即可掉道具，此时还没被击毁；标记消失后不再继续享有携带者优先级。
掉落本身不新增奖励，实际拾取仍使用已有分类型奖励。

启发式 HUNT 给仍携带道具的目标一个有限的 24px 等价距离优先项，
不是无条件追红坦。独立启发式仍优先处理迫近子弹和基地紧急威胁。
独立启发式的拾取不再受固定 64px 半径限制，而是使用共享 A* 的真实
移动＋拆砖路径成本和分类型成本预算：缺命时加命、尚未满级的星值得更长路线，
已有护盾 / 冻结或满级星的预算降低；无路或超过预算就回到战斗。
PPO 仍自行选择是否调用 GET_ITEM，并未被规则强制接管。

`item_drops` 统计真实掉落，`item_opportunities` 包括回合起点已有道具和新掉落。
评测拾取率为总拾取数 / 总出现机会，无机会时为 `null`。
这不是“可安全拾取率”：不可达道具、被后来掉落覆盖的道具也会计入出现机会，
需要结合基地失败率、路径和实战录像解释。

## 实验规范

胜率评测始终运行 `full`，固定关卡、种子、时长和模型。
奖励各分项、真实事件计数、失败类型、停滞时间必须一起看。
模型附带源码/ROM/环境签名；改语义后重新训练或明确建立新实验，不绕过签名续训。
`--warm-start` 是明确的权重迁移，不是 `--resume`。已验证的 v3→残砖 v4 布局变化
按堆叠帧映射首层权重，新通道置零；v4→危险表征 v5 为每帧保留旧 45 通道权重，
追加的危险/携带道具两个通道权重置零，其余网络参数逐项复制。
两种迁移都重新开始优化器、步数和课程进度，并记录来源与上游迁移记录。
初始旧信息处理能力可以保留，但宏动作含义改进后旧策略效果可能变化，需要重新评测。

v5→v6 外边界规则修正不改 47 通道布局。经明确审核的 `--continue-from` 接续路径
保留权重、优化器、训练步数和课程进度，不再次回到击杀课程起点。
新回合重置模拟器与未完成的观测历史；普通 `--resume` 的严格版本检查不放宽。

此前约 1046 万步实验已暂停。v7 占位位修正后的恢复实验，不默认接续其优化器：
旧权重只作为一个与从零训练并列的对照组，重新初始化训练状态。
固定预算、技能验收与完整关卡胜率分开报告；短实验零通关不等于算法不可能成功，
更不能据此自动延长至另一轮千万步。
